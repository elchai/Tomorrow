# Desktop UI/UX Audit — Tomorrow (v0.4)

Audit date: 2026-05-26
Viewports audited: 1920×1080 and 1440×820
Screenshots: `docs/audits/2026-05-26-mega-audit/02-desktop-screenshots/`

---

## Severity legend

- **P0** — Broken / unusable / professionally embarrassing for a B2B demo.
- **P1** — Highly visible defect that erodes trust; fix this sprint.
- **P2** — Polish / inconsistency; non-blocking but noticeable.
- **P3** — Nit / micro-tuning; safe to defer.

## Summary

- **P0:** 4 — drawer→map gray tiles (critical visual bug), inconsistent drawer slide implementations, hidden footer, stale version label.
- **P1:** 9 — login logo legibility, stat-strip vs markers, strategic events, threat-box crowding, intel/LPR drawer overflows, blurry canvas charts, RTL switch direction.
- **P2:** 9 — false-green coverage stat, OSINT marker text overlap, classification scan strobe, popup auto-pan, OSINT popup styling, urgency colour misuse, font baseline shift, OSINT off-state affordance.
- **P3:** 8 — login footer position, drawer close-button hover, forecast card OSINT tag, hamburger accessibility, dead boot-sub overflow rule, RTL border-right semantics, toast/timeline overlap, sim-btn colour conflict.

**Top three fixes that move the needle for a B2B demo:**

1. Call `TomorrowMap.getMap().invalidateSize()` after every drawer toggle (Finding #1) — this is the most visually damaging defect at the demo resolution.
2. Surface the footer (Finding #3) — Daghazahav credit is a contractual deliverable.
3. Bump version label to v0.4 and unify drawer transitions (Findings #2, #4) — code-hygiene wins that protect against future copy/paste.
